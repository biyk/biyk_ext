# trace_viewer — визуальный разбор боевых трейсов

Инструмент для «глазкового» анализа боёв arent: проигрывание трейсов по шагам
(начиная с нулевого раунда — стартовая расстановка), разбор награды за каждый
шаг с попапами-описаниями тегов, статистика по бойцам/командам/раундам.

Полностью автономная папка: читает логи `.ray` **только на чтение**, ничего в
проекте не меняет. Другие агенты могут править `arent/` — конфликта нет.

## Запуск

```bat
cd server\tools\trace_viewer
python serve.py           # http://127.0.0.1:8317/viewer.html + эндпоинт /refresh
```

`serve.py` — тот же статик-сервер, но с GET `/refresh`: перегоняет
`parse_traces.py` по свежим `.ray\traces_all_*.json` и отдаёт JSON. Кнопка
**🔄 Обновить данные** под селектом боя дергает `/refresh` и перезагружает
страницу со свежими данными (battles.js грузится с `?ts=`, так что кэш не мешает).
Можно и по-старому руками: `python parse_traces.py` → Ctrl+F5.
Страница НЕ подтягивает трейсы сама — она читает готовый `battles.js`;
актуальность данных видна по штампу «Данные: <дата> · боёв N из M файлов».

## Что где смотреть

- **Фильтры сверху — каскадные** (иерархия слева направо): «Модель» (кандидат,
  `b.policy`: какой обученной модели принадлежит бой — s3dagger_adv / s4_cover / …) →
  «Наша роль» (класс кандидата) → «Роль врага» (класс оппонента) → «Соперник» (AI оппонента: greedy/battlecast/self — в self-боях это та же модель)
  → «Результат» (win/loss/draw/open). В каждом нижнем
  селекте остаются только значения, реально встречающиеся среди боёв, прошедших
  фильтры выше; уже выбранный ставший невозможным вариант сбрасывается в «все».
  Применяются И (пересечение), каждое изменение мгновенно пересобирает список боёв.
- **Селект «Бой» снизу** — только бои, прошедшие фильтры; рядом счётчик
  «N из M». Метка боя: `id · политика vs оппонент · наш: герои/враги · исход`.
  Текущий бой сохраняется, если он всё ещё под фильтром.
- **Название боя над картой** — поле с полным заголовком `id · политика vs оппонент ·
  наш · исход · шаг N/M (раунд R)`: клик по полю выделяет его целиком (Ctrl+C),
  кнопка 📋 копирует в буфер — удобно вставить в сообщение/макрос.
- **Canvas** — арена честного размера из `arena.scene` (пунктир = движение (золотой — кандидат, серый — оппонент),
  зелёная стрелка = атака с уроном; красная рамка юнита = «вредная» награда
  (без атаки, но +тактический as-if); стены (если появятся в дампе) — серые толстые
  сегменты). **Клик по бойцу** — попап вооружения и характеристик из `arena.tokens`
  (скорость ходьбы в футах и клетках — клетка 5 фт, даль melee, шанс попадания,
  инициатива, таблица оружия с верной/неверной дальностью).
- **Транспорт** — ◀ ▶ по шагам, раундовые кнопки, автоплей, ползунок,
  клавиши ←/→/Home/End/Space. Полоса тиков под ареной — клик = прыжок к шагу
  (первый серый тик — раунд 0, только расстановка, до первого хода).
- **Панель справа** — за что и сколько: base / потенциал / применено / as-if
  со списком тегов и warning'ом ВНИМ; ниже — накопительные итоги боец/раунд/
  команда/бой.
- **Теги кликабельны** (в блоке «As-if тактический» и в статистике) — клик по
  имени показывает попап: что это за награда/штраф и за что именно он
  начисляется (по детекторам `arent/tactics_detect.py`).
- **Таб «Награды и штрафы»** — справочник целиком: таблица базовых событий
  TeamReward (win/loss/draw/mutual/kill/hit/living_cost с весами) и таблица
  всех тактических тегов as-if-шейпера (награды/штрафы/служебные) с весами и описаниями.
  В колонке **вкл** — чекбоксы, которые ПИШУТ напрямую в `server/points.json`
  (`tactics.base.<событие>.enabled` / `tactics.tags.<тег>.enabled`) через POST
  `/points_enabled` в serve.py: read-modify-write под локом, атомарный `os.replace`,
  единственный меняемый путь — прочие ключи (включая `desc`) и порядок сохраняются.
  шейпер перечитывает файл на горячую — перезапуск не нужен. Без serve.py кнопка
  честно сообщает «points.json НЕ изменён» и откатывает галку.
- **Таб «⚖ Тюнинг весов»** — предпросмотр наград/штрафов при новых коэффициентах,
  ничего не пишет на диск (галки вкл/выкл переехали на «Награды и штрафы», здесь только числа):
  дефолты берутся живьём из `server/points.json`
  (serve.py отдаёт его read-only как `/points.json`; без serve.py — из `tagDefaults` дампа).
  Правка веса (применяется при потере фокуса поля) пересчитывает as-if каждого шага:
  в инспекторе появляется строка «as-if (тюнинг) … было …», внизу таба — Σ as-if по текущему
  бою в столбик (наши / враги / всего, было → станет с Δ); Σ по всему массиву боёв
  не считаем и не показываем; изменённые теги помечаются `*` и подсвечиваются.
  «📋 JSON для агента (правки)» копирует в буфер только дифф в формате секции `tactics`
  (`{"tactics":{"weights":{…},"penalties":{…}}}`) — передай его агенту-владельцу
  шейпера, он мержит в points.json; «↺» — сброс правок.

### Быстрый переход через URL

`viewer.html?battle=3&step=5&tab=stats` — открыть сразу нужное: бой по
индексу, шаг (0 = раунд 0) и вкладку (`stats`/`about`/`tags`/`tune`). Удобно шарить
конкретный кейс.

Фильтры тоже задаются из URL: `?fmod=s4_cover&frole=mobile_archer&fpol=greedy&fopp=melee&fout=win`
(невалидные для текущего каскада значения сбросится в «все»).

## Источники данных

| Источник | Награды | Примечание |
|---|---|---|
| `.ray\traces_all_<run>.json` | зависит от дампа | основной: `dump_traces.py` пишет ВСЕ бои (win/loss/draw) в чистом UTF-8; нативные поля team_eval парсер конвертит в формат вьюера |
| `stage3_traces_*.log` | ❌ | legacy (на 24.10 удалены, парсер оставлен на всякий) |
| `stage3_reward_hack*.log` | ✅ as-if с тегами | legacy; UTF-16 + mojibake, парсер чинит таблицей |

Важно: обычный `traces_all_s4_cover.json` снят старым дампером с `counters=None` —
в его шагах пустые `reward_breakdown.tags` (бой помечается бейджем «без as-if
тегов»). Для тегов рядом лежит `dump_traces_tagged.py` — моя обёртка над
`dump_traces.py` (его не правим): гоняет те же бои с `counters=Counters()` и
record_only-шейпером (награда остаётся честным исходом, теги пишутся в tags),
результат — `.ray\traces_all_<run>_tagged.json`. Парсер при скане предпочитает
`_tagged`-версию обычному файлу (дублей в списке боёв нет). Команда:
```bat
cd server
set PYTHONPATH=%CD%
arent\.venv\Scripts\python.exe tools\trace_viewer\dump_traces_tagged.py s4_cover
```

С 24.10 `dump_traces.py` (чужой) вшивает в каждый бой `row["arena"]` — статичное
определение поля: `scene.{width,height,gridSize}` в px (реальные размеры: 1600×1300 →
32×26 клеток «large», 1100×1100 → 22×22 «medium»), `walls` (сегменты points.A/B в px),
`tokens` (стартовые позиции/HP/оружие) и метаданные генерации (`field_profile`,
`archetype`, `deployment`, `layout`, `n_walls`). Парсер берёт из арены настоящий размер
сетки (берётся максимум с координатами — юниты иногда выходят за декларируемое поле),
стены конвертит px→клетки, а `tokens` складывает в `battle.gear` (попап по клику на бойца);
вьюер рисует поле честного размера. Клетки board/tokens — `[row,col]`: вьюер рисует col→X, row→Y.
Моя обёртка `dump_traces_tagged.py` тоже подтянута и пишет арены + теги сразу.
В текущих дампах `walls` пустые (n_walls=0, арены открытые) — укрытий/terrain по-прежнему
нет, для них их надо добавлять в выгрузку `dump_traces.py`. Бои из старых дампов без
арены получают сетку по максимумам координат (как раньше).

Под шапкой боя печатается штамп данных: когда перегенерирован `battles.js`, из каких
файлов и предупреждение, если as-if-теги пусты — по нему видно, устарели данные или нет.

## Файлы

- `parse_traces.py` — парсер (stdlib, без зависимостей)
- `serve.py` — сервер статики + `/refresh` для кнопки 🔄, `/points.json` (чтение
  секции tactics для обоих табов) и POST `/points_enabled` (чекбоксы «вкл» пишут
  enabled в points.json) (stdlib)
- `dump_traces_tagged.py` — дамп с as-if-тегами (обёртка над чужим `.ray/dump_traces.py`)
- `viewer.html` — вьювер (self-contained, без CDN/интернета)
- `battles.json` / `battles.js` — сгенерированные данные (не руками)
